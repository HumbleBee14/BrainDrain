# Distillation Stage 1 — Local Testing Guide

> How to verify the Stage 1 feature end to end (implementation plan §4).
> Written so this can be tested any time after merge without re-deriving the details.

---

## 1. What you need before starting

| Requirement | Why | Notes |
| --- | --- | --- |
| Any documents totalling **~15k+ characters** (≈8–10 pages) | The parity report needs the golden holdout, and a holdout is only taken when the run produces **≥ 10 chunks** (chunks are ~1500 chars). | Content doesn't matter — old dummy/test docs are fine. Below the threshold, training still works but the parity section shows the "no held-out set" empty state. |
| A teacher | Distill mode requires one by design. | Cheapest: **"Use my configured LLM"** — one click, reuses the tenant LLM key server-side, nothing new to configure. Or any OpenAI-compatible endpoint + key. |
| A judge | The parity suite scores through the tenant LLM judge. | Already covered by the tenant LLM settings. If judge == teacher, the UI shows the inflation notice — that's expected. |
| A GPU path | Distill training is a normal SFT pass. | Local CUDA GPU or Modal, same as quick mode. |

Things that will NOT work (by design, verify they fail cleanly):

- **Imported JSONL datasets** in distill mode → 400 "This dataset was not generated by a teacher…"
- **Distill training job on any non-teacher dataset** → same 400.
- **Restricted-host teacher without the acknowledgment checkbox** → Start blocked / 400 carrying the policy.
- **Teacher on a non-public/private URL** → rejected at the API (and re-checked in the worker).

## 2. Start the stack

```bash
make infra          # PostgreSQL, Redis, MinIO
make temporal       # Temporal server
make migrate        # must report 29 migrations (029 = training_jobs.teacher_config)
make dev-api        # Rust API
make dev-workers    # Python Temporal worker (needs the GPU env for training/eval)
make dev-web        # dashboard
```

## 3. Happy path (UI)

1. Project → upload the documents → **Parse Documents**.
2. Click **Distill a Larger Model** (next to One-Click Fine-Tune).
3. Teacher step: pick **Use my configured LLM** (zero setup) — policy badge appears.
4. Student: keep the default (smallest catalog model is the cheapest test).
5. Advanced (optional): defaults are correct — examples per chunk 5, held-out share 10%.
6. **Generate from teacher & train.**

## 4. What to verify (the §4 checklist)

1. **Dataset provenance** — dataset page shows the badge
   `Generated by {model} @ {host}`; `datasets.config.teacher` contains
   `{host, model, policy, cot, generated_at}` and **no key**. A
   `_golden.jsonl` exists next to the dataset in object storage.
2. **Training job** — job row has `mode = 'distill'`, model name carries
   `-distill-`, and `training_jobs.teacher_config` holds the teacher block
   (any `api_key` value starts with `enc:v1:` — never plaintext).
3. **Evaluation** — scores contain a `teacher_parity` section
   (`parity`, `win_rate`, `tie_rate`, `agreement`, `n`); the evaluation page
   shows *"Matches the teacher on X% of held-out tasks"* with the
   win/tie/loss bar; the model page shows the parity tile.
4. **Deploy gate** — deploy works with `DEPLOY_MIN_TEACHER_PARITY` unset
   (report-only default). Set `DEPLOY_MIN_TEACHER_PARITY=0.99`, restart the
   API, deploy again → blocked with the teacher-parity reason. Unset it after.
5. **Policy enforcement** — pick a restricted-host teacher
   (e.g. base URL `https://api.openai.com/v1`) without ticking the
   acknowledgment → blocked; with the checkbox ticked → proceeds.
6. **Negative paths** — import a JSONL dataset and try a distill training job
   against it → clear 400; tiny doc set (< 10 chunks) → run succeeds, parity
   section shows the empty state instead of numbers.

## 5. API-level smoke (optional, no UI)

```bash
# Policy badge endpoint
curl -s -X POST localhost:8000/api/v1/teachers/classify \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"api_base_url":"https://api.openai.com/v1","model":"anything"}'
# → {"policy":"restricted"}

# Curated teacher catalog
curl -s localhost:8000/api/v1/teachers/catalog -H "Authorization: Bearer $TOKEN"

# Full distill pipeline (teacher = your configured LLM endpoint)
curl -s -X POST localhost:8000/api/v1/projects/$PROJECT_ID/full-pipeline \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "base_model": "unsloth/Llama-3.2-1B-Instruct",
    "training_config": {"method": "qlora", "mode": "distill"},
    "teacher": {"api_base_url": "<your llm base url>", "model": "<teacher model>", "api_key": "<key>"}
  }'
```

Costs: datagen is a handful of teacher LLM calls (billed by the teacher's
provider); training/eval is one small SFT run + eval on your GPU path. No
platform-hosted teacher exists in Stage 1, so there is no platform GPU spend
for the teacher itself.
